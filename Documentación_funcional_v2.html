1. Visión General y Arquitectura Tecnológica

1.1 Propósito del Sistema

El Asistente de Presupuesto Operativo Anual es una aplicación web interactiva (wizard guiado) que automatiza, consolida y facilita la planificación financiera en la iglesia local. Guía paso a paso al Tesorero y al Director de Mayordomía desde la conciliación de feligresía hasta el informe ejecutivo final para la Junta de Iglesia y el Concilio de Mayordomía.

2. Gestión de Seguridad, Control de Accesos y Multitenancy

2.1 Acceso, registro y solicitud de perfil

El sistema opera bajo una política de lista blanca (Allowlist): solo las cuentas registradas y activas en usuarios_autorizados pueden usar el asistente. Nadie es expulsado por no tener acceso: toda persona que inicia sesión con Google OAuth llega a la pantalla de bienvenida, que es el lugar donde espera su autorización. El acceso al asistente se habilita después, desde ahí.

  1. Inicio de sesión: al entrar, el sistema registra a la persona en usuarios_registrados (correo, nombre, primer y último acceso) y calcula su estado de acceso: activo, pendiente (aún sin autorizar) o inactivo (autorizado pero desactivado). En todos los casos la persona pasa a la bienvenida.
  2. Pantalla de bienvenida: muestra su estado y un tutorial interactivo de las 5 fases. El botón Entrar al asistente aparece siempre, pero permanece deshabilitado hasta que la persona tenga acceso activo. El botón Verificar acceso vuelve a consultar el estado; cuando el superadministrador la autoriza, al verificar el botón del asistente se habilita.
  3. Solicitud de acceso: la persona pendiente elige su perfil (Pastor, Tesorero, Director de Mayordomía o Anciano asesor) y su iglesia. La solicitud no concede acceso; solo informa al superadministrador. En la primera visita la ventana se abre sobre la pantalla oscurecida, pero se puede cerrar con Más tarde y retomar después con Cambiar mi selección, de modo que nadie queda atrapado (por ejemplo, si aún no hay iglesias registradas).
  4. Autorización: el superadministrador revisa las solicitudes y asigna rol, iglesias y estado (ver 2.4).

Estructura de la Allowlist (usuarios_autorizados):

  • Email: correo de Google, siempre en minúsculas.
  • Nombre: identificación del usuario.
  • Rol: superadmin, pastor, tesorero, director_mayordomia, anciano_asesor.
  • Iglesia por defecto (iglesia_id): opcional; las iglesias asignadas viven en usuario_iglesias.
  • Estado: Activo / Inactivo.

2.2 Soporte Multitenancy (Múltiples Iglesias / Grupos)

  • Un usuario puede tener asignadas varias iglesias mediante la tabla de relación usuario_iglesias (N a N). El superadministrador ve todas las iglesias.
  • Selector de Iglesia Activa: en el encabezado del asistente, un desplegable permite elegir la iglesia sobre la cual se elabora el presupuesto. Junto a él hay un selector del año de presupuesto; existe un único presupuesto por iglesia y año.
  • Aislamiento por RLS: todas las tablas tienen RLS. Las consultas se filtran por las iglesias del usuario y toda escritura de presupuestos, agrupaciones y catálogo pasa por funciones RPC (security definer) que revalidan rol e iglesia; las tablas solo exponen lectura.

2.4 Módulo de Administración de Usuarios (superadministrador) Nuevo

  • Lista a todas las personas que han iniciado sesión y/o están autorizadas, con filtros Todos / Pendientes / Con acceso / Desactivados, búsqueda por nombre o correo, el perfil e iglesia que solicitaron y su último acceso.

3. Flujo del Asistente (Proceso en 5 Fases) y Estados de Persistencia

3.1 Gestión de Borradores y Persistencia (Ciclo de Vida)

Cada presupuesto registrado en el sistema poseerá un estado dentro de la tabla presupuesto_encabezado:

Estado Descripción Permisos
borrador El presupuesto está en proceso de elaboración por las fases 1 a 4. Superadmin, Tesorero y Director de Mayordomía pueden editar (ver 2.3).
en_revision El presupuesto está cerrado por la tesorería y en evaluación por el Concilio. Solo lectura para consulta.
aprobado Presupuesto cerrado definitivamente y presentado ante la Junta. Lectura y generación de reportes finales.

Guardado Automático: Cada vez que el usuario presiona el botón "Siguiente Fase", el sistema ejecuta un UPSERT (insertar o actualizar) en Supabase guardando el progreso de la fase actual, permitiendo retomar el proceso en cualquier momento.

3.2 Descarga de Plantillas de Carga Nuevo

Requerimiento: toda fase que requiera la carga de un archivo incluye un apartado "Descargar plantilla", desde el cual el usuario obtiene un archivo Excel (.xlsx) con las columnas que debe cargar.

Plantilla Fase Columnas del archivo descargable
Plantilla 1 (Secretaría) Fase 1 nombre_completo, categoria (código A, JA o MYA)
Plantilla 2 (ECLESIA 7) Fase 1 nombre_uf, meses_diezmo, meses_ofrenda
Plantilla 3 (Ejecución Mensual ECLESIA 7) Fase 2 mes, diezmos, gastos, ofrenda_uf, ofrenda_global, ingresos_directos
Plantilla 5 (Departamentos) Nuevo Fase 3 departamento, porcentaje_asignado, gasto, miscelaneos, transferencias_entrada, transferencias_salida
Plantilla 4 (Actividades por Departamento) Fase 4 departamento, actividad, importe

La numeración de las plantillas se conserva por orden de creación: la Plantilla 5 pertenece a la Fase 3.

  • El apartado se muestra dentro de la fase, junto a cada zona de carga. La Fase 1 muestra un botón por cada plantilla (dos).
  • El archivo descargable tiene dos hojas: Plantilla (fila de encabezados con los nombres exactos de las columnas) e Instrucciones (propósito, formato y valores permitidos de cada columna).
  • Los nombres de columna de la plantilla son los mismos que el sistema valida al cargar. Si el archivo no coincide, el sistema lo informa antes de procesarlo.
  • La plantilla se genera en el navegador con SheetJS, sin requerir almacenamiento adicional.

4. Especificación Funcional de Módulos y Estructura de Plantillas

FASE 1: Conciliación de Feligresía y Unidades Financieras (UF)

  • Plantilla 1 (Secretaría - .xlsx/.csv): columnas obligatorias nombre_completo y categoria, esta última capturada con código: A = Adulto, JA = Joven, MYA = Niño/Adolescente (en pantallas y reportes se muestra la etiqueta completa). La categoría es una clasificación estadística y no interviene en los cálculos financieros. Un código no válido detiene la carga e indica la fila.
  • Plantilla 2 (ECLESIA 7 - .xlsx/.csv): columnas obligatorias nombre_uf, meses_diezmo (0-12) y meses_ofrenda (0-12). La marca SI/NO de diezma/ofrenda ya no se captura: se deriva de los meses.
  • Procesamiento:
    1. Agrupación automática: por orden de prioridad, (1) la agrupación guardada antes para la iglesia y (2) coincidencias de nombre exactas y únicas. Las sugerencias parciales (fuzzy matching por cobertura de palabras, desde 60%) se ofrecen al agrupar manualmente. Nunca se pisan las decisiones manuales.
    2. Vinculación manual (relación 1 a muchos: 1 UF → N Miembros) en la vista Por miembro, con búsqueda, filtro Solo miembros sin UF y paginación. La vista Por UF es de consulta.
    3. Memoria de agrupación: el botón Guardar agrupación registra los pares miembro → UF de la iglesia (agrupaciones_uf) para reutilizarlos en presupuestos de años posteriores. Cada vínculo muestra su origen: Automática, Guardada, Manual, Quitado o Sin UF.
    4. Resumen de conciliación Nuevo: # Miembros, # agrupados en una UF, # miembros sin UF, # UF, # UF sin miembros (Visitas) y UF diezmantes / en dadivosidad, como control antes de pasar a la Fase 2. Cada UF muestra además cuántos miembros tiene agrupados.

Propósito de las columnas utilizadas en cálculos Nuevo

PlantillaColumnaPara qué se usa
1nombre_completoIdentifica al miembro y permite sugerir y registrar su vinculación con una UF. Su total es el # de Miembros Reales (Fase 5, Sección 1).
2nombre_ufIdentifica la UF (una persona o un grupo, por ejemplo un matrimonio).
2meses_diezmoMeses del año evaluado con diezmo. Una UF con más de 0 meses es Unidad Diezmante; permite desglosarlas en 12, 11 y 10 meses (Fase 5, Sección 1) y alimenta "Miembros que Diezmaron {Año Anterior}" (Sección 2).
2meses_ofrendaMeses del año evaluado con ofrenda. Una UF con más de 0 meses es Unidad en Dadivosidad Sistemática; permite desglosarlas en 12, 11 y 10 meses y alimenta "Miembros que Ofrendaron {Año Anterior}".

Decisión tomada (Fase 1)

  • El criterio de Unidad Diezmante y de Unidad en Dadivosidad son los meses (mayor a 0), no una marca SI/NO.
  • # Miembros Reales (Secretaría) es el número de registros de la Plantilla 1.
  • Visitas son las UF de ECLESIA 7 que no tienen ningún miembro de Secretaría vinculado; los miembros sin UF se cuentan aparte como miembros sin UF.

FASE 2: Captura y Análisis Histórico de Ingresos, Gastos y Saldos ($N-1$)

  • Plantilla 3 (Ejecución Mensual ECLESIA 7 - .xlsx/.csv): columnas obligatorias mes, diezmos, gastos, ofrenda_uf, ofrenda_global e ingresos_directos. Un renglón por mes, sin repetir; el mes se acepta como número (1-12) o por su nombre (Enero, Febrero…).

Propósito de las columnas utilizadas en cálculos Nuevo

ColumnaPara qué se usa
diezmosDiezmos del mes. Su suma anual es el total de Diezmos N-1 de la Matriz de Referencia (Fase 5, Sección 3).
gastosGastos locales del mes. Se restan en el saldo mensual y su suma anual es el total de Gastos N-1.
ofrenda_ufTotal de la ofrenda (100%) depositada en el mes por las unidades financieras identificadas, sin incluir la Ofrenda Global ni los ingresos directos.
ofrenda_globalDepósitos sin nombre del mes, por el monto completo (no el 40%); 0 si no hubo.
ingresos_directosOfrendas depositadas directamente a un departamento. No se dividen: se suman a la Ofrenda Local (60%) para obtener la Ofrenda 60% del mes y, con ella, el saldo mensual.
Ofrenda 100% = Ofrenda UF + Ofrenda Global
Ofrenda Local (60%) = Ofrenda 100% × 0.60
Remesa Asociación (40%) = Ofrenda 100% × 0.40
Ofrenda 60% del Mes = Ofrenda Local (60%) + Ingresos Directos
Saldo Mensual = Ofrenda 60% del Mes - Gastos

Desglose de la remesa Nuevo: al enviar el presupuesto a revisión se guarda, por mes, el desglose de la remesa en historico_ejecucion: 20% de la Ofrenda UF, 16% de la Ofrenda UF, 4% de la Ofrenda UF y el 40% de la Ofrenda Global (concepto OFG). Se calcula; no se captura.

  • Si el archivo no trae los 12 meses, el sistema muestra una alerta con los meses faltantes; los promedios mensuales siempre se calculan entre 12.

Decisión tomada (Fase 2)

  • Las columnas ofrenda_bruta, porcentaje_ofrendas y los cuatro desglose_remesa_* de la versión 2 se sustituyen por ofrenda_uf y ofrenda_global; el desglose de la remesa se deriva.
  • Los ingresos directos se incluyen en la Ofrenda 60% (y en el saldo), sin dividirse.
  • El concepto OFG se trata como Ofrenda Global y entra siempre en el cálculo (0 si no hubo).

Por confirmar (Fase 2)

  • Nombre oficial de los conceptos de desglose de la remesa (20%, 16% y 4%), que el Excel solo identifica por su porcentaje.

Outputs: Resumen anual consolidado con totales de Diezmos, Ofrenda UF, Ofrenda Global, Ofrenda 100%, Ofrenda Local (60%), Remesas (40%), Ingresos Directos, Ofrenda 60%, Gastos y Saldo Anual Neto, más el promedio mensual (anual / 12) de Diezmos, Ofrenda 60% y Gastos Nuevo. El total anual de Ofrenda 60% es la base de la Proyección (Fase 5); el total de Ofrenda Local (60%) es la base del reparto departamental (Fase 3).

FASE 3: Catálogo y Presupuesto Operativo por Departamentos

Catálogo de departamentos Nuevo

Cada iglesia mantiene su propio catálogo de departamentos (tabla catalogo_departamentos). La Fase 3 muestra, sobre la tabla de presupuesto, un panel colapsable "Catálogo de departamentos" que indica cuántos están habilitados (por ejemplo "7 habilitados de 9") y lista cada departamento con su estado y un interruptor. Al final del panel hay un campo para crear un departamento nuevo.

AcciónEfecto en la tabla de la Fase 3Efecto en el catálogo
Habilitar El departamento se agrega a la tabla, con todos sus valores en cero. activo = true.
Deshabilitar El departamento sale de la tabla de este presupuesto (y, por tanto, de las Fases 4 y 5). Si ya tenía valores capturados, el sistema pide confirmación porque se pierden. activo = false. Nunca se borra: puede volver a habilitarse.
Crear El departamento se agrega a la tabla, en ceros. Registro nuevo, habilitado. No admite duplicados, sin distinguir mayúsculas ni acentos; si el nombre existe deshabilitado, el sistema indica que debe habilitarse.
Botón × de la tabla Equivale a deshabilitar el departamento. Igual que Deshabilitar.
Cargar la Plantilla 5 Reemplaza la tabla (con confirmación) por los departamentos del archivo. Los departamentos habilitados del catálogo que no vengan en el archivo se agregan en ceros. Los que estén deshabilitados se omiten, y el sistema lo informa. Los nombres del archivo que aún no existen en el catálogo se registran como habilitados.
  • Regla general: los departamentos habilitados del catálogo son los que aparecen en la tabla; los deshabilitados no.
  • El catálogo solo define qué departamentos existen; no guarda montos. Los valores se guardan con cada presupuesto, por nombre de departamento. Por eso deshabilitar un departamento no modifica presupuestos ya enviados a revisión o aprobados.
  • Permisos: el catálogo se edita con los roles que editan el borrador (Superadmin, Tesorero y Director de Mayordomía) y solo mientras el presupuesto está en borrador; en los demás casos el panel es de solo lectura. Cualquier usuario de la iglesia puede consultarlo. Las escrituras pasan por la función guardar_catalogo_departamentos.
  • Borradores anteriores: al abrir un presupuesto, los departamentos de su tabla que no estén en el catálogo se registran automáticamente como habilitados.
  • El catálogo comienza vacío para cada iglesia: se llena creando departamentos o al cargar la Plantilla 5.

Plantilla 5 y captura por departamento

  • Plantilla 5 (Departamentos - .xlsx/.csv): columnas obligatorias departamento, porcentaje_asignado, gasto, miscelaneos, transferencias_entrada y transferencias_salida. Debe incluir todos los departamentos actuales de la iglesia; si el año nuevo tendrá uno nuevo, se incluye también (o se crea en el catálogo), aunque sea con ceros. Valida que los valores sean numéricos, que no falten nombres y que no haya departamentos repetidos.
  • Inputs por Departamento: % Asignado, Gasto, Gastos Misceláneos, Transferencias Entrantes y Transferencias Salientes; tras cargar el archivo pueden seguir editándose en la tabla. Ingresos (60%) e Ingresos Directos se calculan, no se capturan Nuevo.

Propósito de cada campo Nuevo

CampoOrigenPara qué se usa
% AsignadoCapturaReparte la Ofrenda Local (60%) anual N-1 entre los departamentos. La suma debe ser 100%.
Ingresos (60%)Calculado: Ofrenda Local (60%) anual N-1 × % AsignadoBase del saldo de cada departamento.
GastoCapturaSe resta en el Saldo Parcial y suma al Total Gastos.
Gastos MisceláneosCapturaSuma al Total Gastos.
Ingresos DirectosCalculado: total de Ingresos Directos de la Fase 2 × % AsignadoSuma al Saldo Final.
Transferencias Entrantes / SalientesCapturaAjustan el Saldo Final entre departamentos. Las entrantes deben igualar a las salientes.
Ingresos = Ofrenda Local (60%) anual (N-1) × % Asignado
Ingresos Directos = Total Ingresos Directos (Fase 2) × % Asignado
Saldo Parcial = Ingresos - Gasto
Total Gastos = Gasto + Gastos Misceláneos
Saldo Semifinal = Ingresos - Total Gastos
Saldo Final = Saldo Semifinal + Ingresos Directos + Transf. Entrantes - Transf. Salientes

Validaciones: verificación automática de que ∑ Transf. Entrantes = ∑ Transf. Salientes y de que ∑ % Asignado = 100%. No se puede enviar a revisión si no se cumplen.

Decisión tomada (Fase 3)

  • Doble conteo de ingresos directos: el reparto se hace sobre la Ofrenda Local (60%, sin ingresos directos) y los ingresos directos se suman aparte, una sola vez, repartidos por el mismo % Asignado.
  • El Saldo Final sí resta las transferencias salientes.

Por confirmar (Fase 3)

  • Si el catálogo debe iniciar con una lista sugerida de departamentos para cada iglesia nueva (la versión inicial del sistema sembraba 7); hoy comienza vacío.

FASE 4: Formulación, Ajuste e Inflación del Nuevo Presupuesto ($N$)

  • Configuración Global: % de Inflación (por defecto 5.00%) y % de Crecimiento Proyectado de Ofrenda Nuevo (captura manual; inicia en 0). El crecimiento proyecta la Ofrenda 60% del año nuevo en la Fase 5, Sección 3.
  • Plantilla 4 (Actividades por Departamento - .xlsx/.csv): columnas obligatorias departamento, actividad e importe. El nombre del departamento debe coincidir con el de la Fase 3; los nombres del archivo que no existan en la Fase 3 se señalan en una alerta. El importe se suma por departamento para obtener su Gasto Estimado, que alimenta la Fase 5 (Sección 4).
Gasto Estimado del Departamento = ∑ importe de sus actividades
Total Gasto Estimado = ∑ Gasto Estimado de todos los departamentos
Límite Indexado N (por departamento) = Saldo Final (N-1) × (1 + % Inflación / 100)
  • Si el Gasto Estimado supera el Límite Indexado, el departamento se resalta en rojo como alerta.
  • Monto Aprobado: por defecto igual al Gasto Estimado; se puede ajustar y capturar un comentario explicativo.
  • Cierre y Recálculo: el sistema recalcula el % nuevo de cada departamento sobre el total general aprobado.

Decisión tomada (Fase 4)

  • El Límite Indexado se mantiene como alerta adicional; el reparto del presupuesto sigue la regla de la Proyección (Fase 5, Secciones 3 y 4).

FASE 5: Pantalla Resultante / Salida del Sistema y Exportación

Sección 1: Estadística

-- 1. EXTENSIONES
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- 2. TABLA DE IGLESIAS (MULTITENANCY)
CREATE TABLE public.iglesias (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    nombre TEXT NOT NULL,
    distrito TEXT,
    asociacion TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. TABLA DE USUARIOS AUTORIZADOS (ALLOWLIST)
CREATE TABLE public.usuarios_autorizados (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    email TEXT UNIQUE NOT NULL,
    nombre TEXT NOT NULL,
    iglesia_id UUID REFERENCES public.iglesias(id) ON DELETE CASCADE,
    rol TEXT NOT NULL CHECK (rol IN ('superadmin', 'tesorero', 'secretario', 'director', 'junta')),
    activo BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 4. TABLA DE ENCABEZADO DE PRESUPUESTO (BORRADORES Y DRAFTING)
CREATE TABLE public.presupuesto_encabezado (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    iglesia_id UUID REFERENCES public.iglesias(id) ON DELETE CASCADE,
    anio_evaluado INT NOT NULL, -- Año N-1
    anio_presupuestado INT NOT NULL, -- Año N
    porcentaje_inflacion NUMERIC(5,2) DEFAULT 5.00,
    fase_actual INT DEFAULT 1,
    estado TEXT DEFAULT 'borrador' CHECK (estado IN ('borrador', 'en_revision', 'aprobado')),
    creado_por TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 5. CATÁLOGO DE DEPARTAMENTOS POR IGLESIA
CREATE TABLE public.departamentos (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    iglesia_id UUID REFERENCES public.iglesias(id) ON DELETE CASCADE,
    nombre TEXT NOT NULL,
    activo BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 6. PRESUPUESTO DEPARTAMENTAL (FASE 3 Y FASE 4)
CREATE TABLE public.presupuesto_departamental (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    presupuesto_id UUID REFERENCES public.presupuesto_encabezado(id) ON DELETE CASCADE,
    departamento_id UUID REFERENCES public.departamentos(id) ON DELETE CASCADE,
    porcentaje_anterior NUMERIC(5,2) DEFAULT 0.00,
    gasto_estimado NUMERIC(12,2) DEFAULT 0.00,
    gasto_por_porcentaje NUMERIC(12,2) DEFAULT 0.00,
    comentario_ajuste TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
