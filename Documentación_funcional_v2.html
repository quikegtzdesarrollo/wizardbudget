1. Visión General y Arquitectura Tecnológica

1.1 Propósito del Sistema

El Asistente de Presupuesto Operativo Anual es una aplicación web interactiva (wizard guiado) que automatiza, consolida y facilita la planificación financiera en la iglesia local. Guía paso a paso al Tesorero y al Secretario desde la conciliación de feligresía hasta el informe ejecutivo final para la Junta de Iglesia y el Concilio de Mayordomía.

2. Gestión de Seguridad, Control de Accesos y Multitenancy

2.1 Módulo Super Administrador (Allowlist)

El sistema opera bajo una política de lista blanca estricta (Allowlist). Únicamente las cuentas de correo electrónico previamente registradas y activas en la tabla usuarios_autorizados de Supabase podrán iniciar sesión con Google OAuth.

Estructura de la Allowlist:

  • Email: Correo electrónico de Google.
  • Nombre: Identificación del usuario.
  • Iglesia Asignada (iglesia_id): ID de la iglesia donde opera.
  • Rol: superadmin, tesorero, secretario, director, junta.
  • Estado: Activo / Inactivo.

2.2 Soporte Multitenancy (Múltiples Iglesias / Grupos)

Para soportar que un mismo usuario opere una o más iglesias o grupos pequeños:

  • Un usuario puede tener asignadas varias iglesias en la base de datos.
  • Selector de Iglesia Activa: En el encabezado superior (navbar) del asistente, el usuario visualizará un desplegable para seleccionar la iglesia sobre la cual está elaborando el presupuesto.
  • Aislamiento por RLS: Las consultas y guardados en Supabase filtrarán automáticamente todos los registros utilizando la variable global del iglesia_id seleccionado en la sesión.

3. Flujo del Asistente (Proceso en 5 Fases) y Estados de Persistencia

3.1 Gestión de Borradores y Persistencia (Ciclo de Vida)

Cada presupuesto registrado en el sistema poseerá un estado dentro de la tabla presupuesto_encabezado:

Estado Descripción Permisos
borrador El presupuesto está en proceso de elaboración por las fases 1 a 4. Tesorero / Secretario pueden editar.
en_revision El presupuesto está cerrado por la tesorería y en evaluación por el Concilio. Solo lectura para consulta.
aprobado Presupuesto cerrado definitivamente y presentado ante la Junta. Lectura y generación de reportes finales.

Guardado Automático: Cada vez que el usuario presiona el botón "Siguiente Fase", el sistema ejecuta un UPSERT (insertar o actualizar) en Supabase guardando el progreso de la fase actual, permitiendo retomar el proceso en cualquier momento.

 Feligresía    Histórico de Departamental  Inflación  Salida

3.2 Descarga de Plantillas de Carga Nuevo

Requerimiento: toda fase que requiera la carga de un archivo debe incluir un apartado "Descargar plantilla", desde el cual el usuario obtenga un archivo Excel (.xlsx) con las columnas que debe cargar.

Plantilla Fase Columnas del archivo descargable
Plantilla 1 (Secretaría) Fase 1 id_miembro, nombre_completo, categoria
Plantilla 2 (ECLESIA 7) Fase 1 nombre_uf, marcador_uf, diezma, ofrenda, meses_diezmo, meses_ofrenda
Plantilla 3 (Ejecución Mensual ECLESIA 7) Fase 2 mes, diezmos, ofrenda_bruta*, gastos, porcentaje_ofrendas*, desglose_remesa_20, desglose_remesa_16, desglose_remesa_4, desglose_remesa_ofg, ingresos_directos
Plantilla 4 (Actividades por Departamento) Fase 4 departamento, mes, actividad, importe

* Columnas pendientes de confirmar (ver recuadro Por confirmar de la Fase 2).

  • El apartado se muestra dentro de la fase, junto a cada zona de carga. La Fase 1 muestra un botón por cada plantilla (dos).
  • El archivo descargable contiene una fila de encabezados con los nombres exactos de las columnas, en el orden de esta especificación.
  • Los nombres de columna de la plantilla son los mismos que el sistema valida al cargar. Si el archivo cargado no coincide, el sistema lo informa antes de procesarlo.
  • La plantilla se genera en el navegador con SheetJS (ya incluida en el stack), sin requerir almacenamiento adicional.
  • Deseable: una segunda hoja Instrucciones con el propósito, el formato y los valores permitidos de cada columna.

4. Especificación Funcional de Módulos y Estructura de Plantillas

FASE 1: Conciliación de Feligresía y Unidades Financieras (UF)

  • Plantilla 1 (Secretaría - .xlsx/.csv): Columnas obligatorias: id_miembro, nombre_completo, categoria (Adulto, Joven, Niño/Adolescente). La categoría es una clasificación estadística y no interviene en los cálculos financieros.
  • Plantilla 2 (ECLESIA 7 - .xlsx/.csv): Columnas obligatorias: nombre_uf, marcador_uf, diezma (SI/NO), ofrenda (SI/NO), meses_diezmo (0-12) Nuevo, meses_ofrenda (0-12) Nuevo.
  • Procesamiento:
    1. Fuzzy Matching para sugerencias de vinculación entre archivos.
    2. Vinculación manual (Relación 1 a Muchos: 1 UF → N Miembros).
    3. Clasificación automática: Registros no asociados se etiquetan como Visita; asociados quedan como Miembro.
    4. Resumen de conciliación Nuevo: al terminar la vinculación se muestran # de Miembros, # de Visitas, # de UF, # de UF diezmantes y # de UF en dadivosidad, como control antes de pasar a la Fase 2. Incluye también el total de miembros asociados a cada UF (calculado por la vinculación).

Propósito de las columnas utilizadas en cálculos Nuevo

Plantilla Columna Para qué se usa
2 nombre_uf Identifica la UF y permite sugerir y registrar su vinculación con los miembros.
2 diezma Cuenta las Unidades Diezmantes (Fase 5, Sección 1) y alimenta "Miembros que Diezmaron {Año Anterior}" (Fase 5, Sección 2).
2 ofrenda Cuenta las Unidades en Dadivosidad Sistemática (Fase 5, Sección 1) y alimenta "Miembros que Ofrendaron {Año Anterior}" (Fase 5, Sección 2).
2 meses_diezmo Número de meses del año evaluado con diezmo. Permite desglosar las Unidades Diezmantes en 12, 11 y 10 meses (Fase 5, Sección 1).
2 meses_ofrenda Número de meses del año evaluado con ofrenda. Permite desglosar las Unidades en Dadivosidad en 12, 11 y 10 meses (Fase 5, Sección 1).

Por confirmar (Fase 1)

  • Criterio de "Unidad Diezmante" y "Unidad en Dadivosidad": en el Excel se cuentan con la marca SI/NO, que no se deriva de los meses, y el conteo no excluye a las Visitas. Definir si el criterio es la marca o los meses, y si las Visitas se cuentan.
  • # Miembros Reales (Secretaría): en el Excel es un valor capturado a mano. En esta especificación se entiende como el número de registros de la Plantilla 1.

FASE 2: Captura y Análisis Histórico de Ingresos, Gastos y Saldos ($N-1$)

  • Plantilla 3 (Ejecución Mensual ECLESIA 7 - .xlsx/.csv): Columnas obligatorias: mes (1-12), diezmos, ofrenda_bruta, gastos, porcentaje_ofrendas, desglose_remesa_20 Nuevo, desglose_remesa_16 Nuevo, desglose_remesa_4 Nuevo, desglose_remesa_ofg Nuevo, ingresos_directos Nuevo.
Ofrenda Local (60%) = Ofrenda Bruta × 0.60
Remesa Asociación (40%) = Ofrenda Bruta × 0.40
Saldo Neto Mensual = Ofrenda Local (60%) - Gastos Locales

Propósito de las columnas utilizadas en cálculos Nuevo

Columna Para qué se usa
diezmos Diezmos del mes. Su suma anual es el total de Diezmos N-1 de la Matriz de Referencia (Fase 5, Sección 3).
gastos Gastos locales del mes. Se restan en el saldo mensual y su suma anual es el total de Gastos N-1.
desglose_remesa_20, desglose_remesa_16, desglose_remesa_4 Conceptos en que se desglosa la remesa (40%) del mes. Su suma es la base para derivar la Ofrenda 100% y la Ofrenda Local (60%).
desglose_remesa_ofg Monto "OFG" del mes (no es un porcentaje). Se suma a los conceptos anteriores para obtener la remesa.
ingresos_directos Ofrendas directas del mes. Se suman a la Ofrenda Local (60%) para calcular el saldo mensual y la Ofrenda 60% anual.

Cálculo a partir de las nuevas columnas Nuevo

Remesa Asociación (40%) = desglose_remesa_20 + desglose_remesa_16 + desglose_remesa_4 + desglose_remesa_ofg
Ofrenda 100% = Remesa Asociación × 100 / 40
Ofrenda Local (60%) = Ofrenda 100% × 0.60
Ofrenda 60% del Mes = Ofrenda Local (60%) + Ingresos Directos
Saldo Mensual = Ofrenda 60% del Mes - Gastos

Por confirmar (Fase 2)

  • ofrenda_bruta y porcentaje_ofrendas: el Excel no las usa, porque parte de la remesa (40%) desglosada. Definir si se cargan o se sustituyen por el desglose.
  • Las fórmulas originales de esta fase no incluyen ingresos directos en el saldo; el Excel sí los incluye en la "Ofrenda 60%".
  • En el Excel algunos meses suman el concepto OFG a la remesa y otros no. Aquí se normaliza sumándolo siempre (0 si está vacío).
  • Nombre de los conceptos de desglose (20%, 16%, 4% y OFG), que el Excel solo identifica por su porcentaje.

Outputs: Resumen anual consolidado con totales de Diezmos, Ofrendas Brutas, Ofrenda Local (60%), Remesas (40%), Ingresos Directos, Gastos y Saldo Anual Neto, más el promedio mensual (anual / 12) de Diezmos, Ofrenda 60% y Gastos Nuevo. El total anual de Ofrenda 60% es la base del reparto departamental (Fase 3) y de la Proyección (Fase 5).

FASE 3: Catálogo y Presupuesto Operativo por Departamentos

  • Gestión del Catálogo Departamental: Antes de ingresar montos, la tesorería dispondrá de una pantalla para Activar, Desactivar o Agregar departamentos personalizados de su iglesia local.
  • Inputs por Departamento: Nombre, % Asignado, Gasto, Gastos Misceláneos, Ingresos Directos, Transferencias Entrantes, Transferencias Salientes. Ingresos (60%) se calcula, no se captura Nuevo.

Propósito de cada campo Nuevo

Campo Origen Para qué se usa
% Asignado Captura Reparte la Ofrenda 60% anual N-1 entre los departamentos. La suma debe ser 100%.
Ingresos (60%) Calculado: Ofrenda 60% anual N-1 × % Asignado Base del saldo de cada departamento.
Gasto Captura Se resta en el Saldo Parcial y suma al Total Gastos.
Gastos Misceláneos Captura Suma al Total Gastos.
Ingresos Directos Captura Suma al Saldo Final.
Transferencias Entrantes / Salientes Captura Ajustan el Saldo Final entre departamentos. Las entrantes deben igualar a las salientes.
Ingresos = Ofrenda 60% anual (N-1) × % Asignado
Saldo Parcial = Ingresos - Gasto
Total Gastos = Gasto + Gastos Misceláneos
Saldo Semifinal = Ingresos - Total Gastos
Saldo Final = Saldo Semifinal + Ingresos Directos + Transf. Entrantes - Transf. Salientes

Validaciones: Verificación automática de que ∑ Transf. Entrantes = ∑ Transf. Salientes, y de que ∑ % Asignado = 100% Nuevo.

Por confirmar (Fase 3)

  • La Ofrenda 60% anual ya incluye los ingresos directos (Fase 2) y esos mismos ingresos se vuelven a sumar en la columna "Ingresos Directos" del Saldo Final: riesgo de doble conteo, presente en el Excel.
  • La fórmula del Saldo Final en el Excel no resta las transferencias salientes; la de esta especificación sí.
  • Los datos por departamento (Gasto, Misceláneos, Ingresos Directos y transferencias) se capturan manualmente; esta fase no tiene plantilla de carga.

FASE 4: Formulación, Ajuste e Inflación del Nuevo Presupuesto ($N$)

  • Configuración Global: Módulo de ajustes para definir el % de Inflación (Por defecto: 5.00%) y el % de Crecimiento Proyectado de Ofrenda Nuevo (captura manual, sin valor por defecto; se usa para proyectar la Ofrenda 60% del año nuevo en la Fase 5, Sección 3).
  • Plantilla 4 (Actividades por Departamento - .xlsx/.csv): Columnas obligatorias: departamento, mes (1-12), actividad, importe. El importe de las actividades se suma por departamento para obtener su Gasto Estimado, que alimenta la Fase 5 (Sección 4) Nuevo.
Gasto Estimado del Departamento = ∑ importe de sus actividades Nuevo
Total Gasto Estimado = ∑ Gasto Estimado de todos los departamentos Nuevo
Límite Indexado N = Saldo Operativo (N-1) × (1 + % Inflación / 100)

Por confirmar (Fase 4)

  • El Excel no usa el saldo del año anterior ni la inflación para limitar el gasto: el % de cada departamento se asigna sobre la proyección de ofrenda del año nuevo (Fase 5, Secciones 3 y 4). Definir si el Límite Indexado se mantiene como alerta adicional o se sustituye por esa regla.
  • Si el importe solicitado supera el límite indexado, el departamento se resalta en rojo.
  • Permite ajustar el monto aprobado y capturar un comentario explicativo.
  • Cierre y Recálculo: El sistema recalcula los nuevos porcentajes de asignación departamental sobre el total general aprobado.

Sección 3: Proyección + {Año Nuevo}

Gastos N = ∑ Gasto por % de todos los departamentos (Sección 4) Nuevo

La Proyección Ofrenda 60% N es la base del "Gasto por %" de la Sección 4. El % de incremento es un indicador informativo para el Concilio y no restringe el presupuesto.

5. Script SQL para Supabase (Base de Datos y RLS)

-- 1. EXTENSIONES
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- 2. TABLA DE IGLESIAS (MULTITENANCY)
CREATE TABLE public.iglesias (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    nombre TEXT NOT NULL,
    distrito TEXT,
    asociacion TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. TABLA DE USUARIOS AUTORIZADOS (ALLOWLIST)
CREATE TABLE public.usuarios_autorizados (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    email TEXT UNIQUE NOT NULL,
    nombre TEXT NOT NULL,
    iglesia_id UUID REFERENCES public.iglesias(id) ON DELETE CASCADE,
    rol TEXT NOT NULL CHECK (rol IN ('superadmin', 'tesorero', 'secretario', 'director', 'junta')),
    activo BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 4. TABLA DE ENCABEZADO DE PRESUPUESTO (BORRADORES Y DRAFTING)
CREATE TABLE public.presupuesto_encabezado (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    iglesia_id UUID REFERENCES public.iglesias(id) ON DELETE CASCADE,
    anio_evaluado INT NOT NULL, -- Año N-1
    anio_presupuestado INT NOT NULL, -- Año N
    porcentaje_inflacion NUMERIC(5,2) DEFAULT 5.00,
    fase_actual INT DEFAULT 1,
    estado TEXT DEFAULT 'borrador' CHECK (estado IN ('borrador', 'en_revision', 'aprobado')),
    creado_por TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 5. CATÁLOGO DE DEPARTAMENTOS POR IGLESIA
CREATE TABLE public.departamentos (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    iglesia_id UUID REFERENCES public.iglesias(id) ON DELETE CASCADE,
    nombre TEXT NOT NULL,
    activo BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 6. PRESUPUESTO DEPARTAMENTAL (FASE 3 Y FASE 4)
CREATE TABLE public.presupuesto_departamental (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    presupuesto_id UUID REFERENCES public.presupuesto_encabezado(id) ON DELETE CASCADE,
    departamento_id UUID REFERENCES public.departamentos(id) ON DELETE CASCADE,
    porcentaje_anterior NUMERIC(5,2) DEFAULT 0.00,
    gasto_estimado NUMERIC(12,2) DEFAULT 0.00,
    gasto_por_porcentaje NUMERIC(12,2) DEFAULT 0.00,
    comentario_ajuste TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- HABILITAR ROW LEVEL SECURITY (RLS) EN TODAS LAS TABLAS
ALTER TABLE public.iglesias ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.usuarios_autorizados ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.presupuesto_encabezado ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.departamentos ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.presupuesto_departamental ENABLE ROW LEVEL SECURITY;

TO authenticated
USING (
  EXISTS (
    SELECT 1 FROM public.usuarios_autorizados
    WHERE email = auth.jwt() ->> 'email'
    AND activo = TRUE
  )
);
